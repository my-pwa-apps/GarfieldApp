# Principal Engineering Review - September 7, 2026

## 1. Executive Summary

GarfieldApp is a build-free, vanilla JavaScript PWA for daily English/Spanish comics, archive navigation, offline reading, local favorites, Google Drive sync, sharing, and community rankings. A Cloudflare Pages shell uses a CORS proxy Worker and a SQLite-backed Durable Object favorites API.

**Verdict: Not ready for an unqualified production release sign-off.** Everyday mocked browser journeys are healthy, but reproduced favorite-date, sync, persistence, image, and mobile-accessibility defects remain. The live proxy health check also fails and deployed endpoint behavior does not match this repository. This is not a claim that all existing users or all English fallback sources are blocked.

The largest near-term gains come from making the displayed comic/date a trustworthy state unit, preserving user intent through synchronization and retries, and verifying the exact deployed Worker. Incremental extraction is worthwhile after these behavior contracts have regression protection; a framework rewrite is not justified.

## 6. Highest-Value Improvements

1. Verify the deployed proxy artifact and provider behavior. High user value, high operational risk reduction, medium effort; do not deploy blindly to an unverified account.
2. Make comic bytes, canonical date, favorite, and share state agree (R01/R05). High user/data value, small-to-medium effort, valuable foundation for later refactoring.
3. Protect favorites and votes against reordering, deletion resurrection, and partial commits (R02/R03). High data-integrity and reliability value, medium effort.
4. Make offline data and mobile keyboard behavior truthful (R04/R11). High product/accessibility value, small-to-medium effort.
5. Add failure-path contract tests before extracting features and optimizing startup. High engineering value; incremental extraction is large effort but should reduce future regression costs.

## 7. Cleanup and Simplification

The asset guard passed: no deletion is justified by this review. Existing icon deduplication, dead-code cleanup, batched Fandom lookup, uClick HEAD probing, and module-format cleanup are real improvements worth preserving.

Highest-value simplification is one displayed-comic/date commit path and one transition/error lifecycle, not cosmetic reformatting. Nine historical unresolved-checkbox references were consolidated into canonical entries so the backlog count is usable. The local installed tree has two extraneous optional packages, but they are not proven committed or deployed waste; a clean-install verification is preferable to a new cleanup finding.

## 8. Architecture and Refactoring

The static ES-module design and two small Workers suit the product. No evidence justifies React adoption, a general backend, distributed sharding, or a repository-wide rewrite.

The concrete architecture problem is shared mutable application state, not vanilla JavaScript. Introduce a single authoritative displayed-comic record and pure date helpers, then extract cohesive optional features one at a time. Explicit inputs/events replace implicit `window.*` reads where useful. Trade-off: extra module registration and offline-cache maintenance; safeguard each move with the asset guard, behavioral tests, and visual comparisons. Preserve existing native-host messages and persisted formats.

Per-date Durable Object storage already avoids whole-map rewrites. Keep it while adding transactional invariants. Top-window decrements still scan date shards, but current traffic/latency evidence does not justify a new scaling redesign.

## 9. Security, Privacy, Reliability, and Data

Security strengths: no browser runtime npm dependencies; restrictive script CSP without unsafe-inline scripts; proxy host/protocol and redirect checks in local code; bearer-token audience verification; bounded identity cache; authenticated voting; remote leaderboard text built with DOM APIs. OAuth client IDs are public configuration, not leaked secrets. No confirmed XSS, authentication bypass, or exploitable dependency flaw in shipped browser code was established.

The confirmed security issue is R09's authenticated body-allocation exposure in the shared object. Impact and likelihood are moderate, not an unauthenticated critical exploit. Local proxy policy tests cannot certify the mismatching deployed artifact (R06).

Privacy inventory: local name/email for UI and login hints; access tokens in sessionStorage in normal browsers; full favorites/preferences sent to Drive; Google subject-linked favorite membership retained in the API; rate records retained until cleanup; comic URLs disclosed to source/fallback proxy operators. Hosted Stripe data handling is outside this codebase. R10 causes unnecessary retention of expired identity-linked rate records. No evidence of tokens being explicitly printed by application logging was found.

Product decision still needed: describe community contribution and retention separately from the Drive-sync sign-in promise, and decide whether disconnect should only stop syncing or offer deletion of retained server data. No legal-compliance verdict or speculative privacy feature backlog was manufactured. Review production telemetry/redaction and retention policies with authorized dashboard access.

Other limitations: Worker Google verification calls have no explicit timeout and transient upstream failures enter the negative identity cache; this is a documented resilience concern, not separately load-tested here. The source orchestrator has per-request deadlines but no overall end-to-end cancellation budget; source latency should be measured in R15 rather than guessed.

## 12. UX and Accessibility

Existing icon labels, touch-target checks, themes, reduced-motion CSS, settings/leaderboard focus helpers, and automated axe journeys are useful. Preserve them. The concrete gaps are mobile keyboard focus (R11), permanently stale image alt text (R13), mixed-language failures (R17), and misleading success/recovery state for broken images and sync (R05/R08).

Lighthouse accessibility 100 is not proof of full accessibility: it did not identify the reproduced mobile focus problem. Actual comic dialogue has no text equivalent established by this review; obtaining accurate, permitted source descriptions requires a product/content decision, not invented transcripts. No redesign of the established UI is recommended.

The main maintenance cost is implicit cross-feature state and test doubles that omit failure semantics. Prioritize focused runtime tests and small modules over broad style enforcement changes. ## 18. Final Verdict

**Not ready for unconditional release sign-off.** Confidence is high in the local defect findings and medium in overall production readiness because deployed source/dashboard settings and credentialed flows were not inspected. Release-blocking concerns for this assessment are incorrect favorite identity, sync/transaction data integrity, offline/image recovery, mobile keyboard access, and unresolved live proxy verification. There is no evidence-backed Critical classification.

Top three next actions:
1. Identify the exact deployed proxy and restore or explicitly disposition the failing live health gate.
2. Fix canonical comic/date/image commits and add the reproductions as permanent regression tests.
3. Implement conflict-aware Drive sync and atomic vote persistence, then validate offline upgrades and mobile focus before sign-off.

Review-only changes: backlog reconciliation and this report. Application code, tests, lockfile, sitemap, package version, and service-worker version are unchanged; no production deployment was performed. Generated test/audit reports remain ignored. No version bump was made for these internal documentation deliverables.
